# LexoraAI — RAG Pipeline

> A production-grade **Retrieval-Augmented Generation** pipeline. Upload documents, ask questions in natural language, and get grounded answers backed by your own data.

## Architecture

```
┌─────────────────────────────────────────────────────┐
│                    FastAPI (port 8000)               │
│  POST /upload  ─►  parse → chunk → embed → store    │
│  POST /query   ─►  embed → search → prompt → LLM    │
│  GET  /documents ─► metadata list / detail           │
└────────────┬──────────────────────┬─────────────────┘
             │                      │
      ┌──────▼──────┐        ┌──────▼──────┐
      │ PostgreSQL   │        │  ChromaDB   │
      │  (metadata) │        │  (vectors)  │
      └─────────────┘        └─────────────┘
```

**Supported document types:** PDF · DOCX · TXT  
**Vector store:** ChromaDB (self-hosted)  
**LLM providers:** OpenAI GPT-4o-mini · Google Gemini 1.5 Flash  
**Embedding providers:** OpenAI text-embedding-3-small · HuggingFace all-MiniLM-L6-v2 (offline)

## Quick Start (Docker)

### 1. Clone & configure

```bash
git clone https://github.com/yourname/LexoraAI.git
cd LexoraAI
cp .env.example .env
```

Edit `.env` and set at minimum:

```env
OPENAI_API_KEY=sk-...          # required for OpenAI provider
# or
GEMINI_API_KEY=AI...           # if using LLM_PROVIDER=gemini
```

### 2. Start all services

```bash
docker-compose up --build
```

This launches three containers:
| Container | Port (host) | Role |
|---|---|---|
| `lexora_api` | **8000** | FastAPI application |
| `lexora_postgres` | 5432 | PostgreSQL 16 |
| `lexora_chromadb` | 8001 | ChromaDB vector store |

### 3. Explore the API

Open **http://localhost:8000/docs** — interactive Swagger UI auto-generated by FastAPI.

## API Reference

### `POST /api/v1/upload`

Upload 1–20 documents (PDF, DOCX, TXT). Processing is asynchronous.

```bash
curl -X POST http://localhost:8000/api/v1/upload \
  -F "files=@/path/to/report.pdf" \
  -F "files=@/path/to/notes.txt"
```

**Response `202 Accepted`:**
```json
{
  "accepted": [
    {"document_id": "uuid-...", "filename": "report.pdf"},
    {"document_id": "uuid-...", "filename": "notes.txt"}
  ],
  "message": "Documents accepted for processing."
}
```

Poll `GET /api/v1/documents/{document_id}` and wait for `"status": "ready"`.

---

### `POST /api/v1/query`

```bash
curl -X POST http://localhost:8000/api/v1/query \
  -H "Content-Type: application/json" \
  -d '{
    "question": "What are the key findings?",
    "top_k": 5,
    "document_ids": ["optional-filter-id"]
  }'
```

**Response `200 OK`:**
```json
{
  "question": "What are the key findings?",
  "answer": "According to the documents, the key findings are...",
  "sources": [
    {
      "document_id": "uuid-...",
      "chunk_index": 3,
      "page_number": 7,
      "text": "The study found that...",
      "relevance_score": 0.92
    }
  ]
}
```

---

### `GET /api/v1/documents`

```bash
curl "http://localhost:8000/api/v1/documents?page=1&page_size=20&status=ready"
```

Query params: `page`, `page_size`, `status` (pending | processing | ready | error)

---

### `GET /api/v1/documents/{id}`

Returns document metadata + preview of the first 10 chunks.

---

### `DELETE /api/v1/documents/{id}`

Removes the document from PostgreSQL, ChromaDB, and the file system.

---

### `GET /api/v1/health`

```bash
curl http://localhost:8000/api/v1/health
```

```json
{"status": "healthy", "app": "LexoraAI", "version": "1.0.0", "chromadb": "ok"}
```

## Configuration

All configuration is via environment variables (`.env` file or system env).

| Variable | Default | Description |
|---|---|---|
| `LLM_PROVIDER` | `openai` | `openai` or `gemini` |
| `OPENAI_API_KEY` | — | Required for OpenAI |
| `OPENAI_MODEL` | `gpt-4o-mini` | OpenAI model name |
| `GEMINI_API_KEY` | — | Required for Gemini |
| `GEMINI_MODEL` | `gemini-1.5-flash` | Gemini model name |
| `EMBEDDING_PROVIDER` | `openai` | `openai` or `huggingface` |
| `EMBEDDING_MODEL_OPENAI` | `text-embedding-3-small` | OpenAI embedding model |
| `EMBEDDING_MODEL_HF` | `all-MiniLM-L6-v2` | HuggingFace model |
| `CHUNK_SIZE_TOKENS` | `512` | Max tokens per chunk |
| `CHUNK_OVERLAP_TOKENS` | `50` | Overlap between chunks |
| `DEFAULT_TOP_K` | `5` | Chunks retrieved per query |
| `MAX_FILE_SIZE_MB` | `50` | Max size per uploaded file |
| `MAX_DOCUMENTS` | `20` | Max files per upload request |

### Switching LLM Providers

**OpenAI (default):**
```env
LLM_PROVIDER=openai
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini
```

**Google Gemini:**
```env
LLM_PROVIDER=gemini
GEMINI_API_KEY=AI...
GEMINI_MODEL=gemini-1.5-flash
```

### Offline / No-API-Key Mode

Set `EMBEDDING_PROVIDER=huggingface` to use a local sentence-transformer model. No API key required for embedding. You still need an LLM key for answer generation.

```env
EMBEDDING_PROVIDER=huggingface
EMBEDDING_MODEL_HF=all-MiniLM-L6-v2
```

## Local Development (without Docker)

```bash
# 1. Create virtual environment
python -m venv venv && source venv/bin/activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Start PostgreSQL and ChromaDB (e.g. via Docker)
docker run -d -e POSTGRES_USER=lexora -e POSTGRES_PASSWORD=lexora_secret \
  -e POSTGRES_DB=lexora -p 5432:5432 postgres:16-alpine

docker run -d -p 8001:8000 chromadb/chroma:0.5.3

# 4. Configure environment
cp .env.example .env
# Edit .env: set CHROMA_HOST=localhost, CHROMA_PORT=8001, DATABASE_URL pointing to localhost

# 5. Run the API
uvicorn app.main:app --reload --port 8000
```

## Cloud Deployment

The same `docker-compose.yml` deploys to any container platform:

### AWS ECS
```bash
# Push images to ECR, then deploy via ECS task definitions
aws ecr get-login-password | docker login --username AWS --password-stdin <ecr-uri>
docker-compose push
```

### GCP Cloud Run
```bash
# Use Cloud SQL for PostgreSQL, deploy api service to Cloud Run
gcloud run deploy lexora-api --image gcr.io/project/lexora-api --platform managed
```

### Azure Container Apps
```bash
az containerapp compose create --compose-file-path docker-compose.yml \
  --resource-group myRG --environment myEnv
```

**Production checklist:**
- Store secrets in AWS Secrets Manager / GCP Secret Manager / Azure Key Vault
- Enable SSL on PostgreSQL
- Mount `upload_data` volume to a persistent store (S3, GCS, Azure Blob)
- Set `DEBUG=false`

## Postman Collection

Import `postman_collection.json` into Postman. Set the `baseUrl` variable to your deployment URL (default: `http://localhost:8000`).

The **Upload Documents** request automatically saves the returned `document_id` to a collection variable, which is reused by subsequent requests.
